# CRN120 Functional Description

## Block description

The CRN120 IC consist of EEPROM, SRAM, NFC interface, Digital Control Unit
(Command interpreter, Anticollsion, Arbiter/Status registers, I°C control and Memory
Interface), Power Management and an I°C slave interface. Energy and data are
transferred via an antenna consisting of a coil with a few tums, which is coupled to
CRN120.

## NFC interface

The passive NFC interface is compliant to the NFC Forum Type 2 Tag standard.

It requires to be supplied by an NFC field (e.g. NFC enabled device) always to be able t
receive appropriate commands and send the related responses.

As defined in NFC Forum for both directions of data communication, there is one start
bit (start of frame) at the beginning of each frame. Each byte is transmitted with an
odd parity bit at the end. The least significant bit of the byte 0 of the selected block is
transmitted first.

For a multi-byte parameter, the least significant byte is always transmitted first. For
example, when reading from the memory using the READ command, byte 0 from the
addressed block is transmitted first, followed by bytes 1 to byte 3 out of this block. The
same sequence continues for the next block and all subsequent blocks.

## CRN120 GPIOs

| Pin | Configuration               | Description                                                                                                             |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| VCC | Output/Active High          | Powers on the IC                                                                                                        |
| FD  | Input/Active High/Interrupt | Detects when the RF field is detected by the IC. This pin is always used and is most important for power related events |
| ED  | Input/Active Low/Interrupt  | Configurable pin for detecting 2 conditions related to the NFC communication while the IC is in range of an RF field    |
### VCC Pin

VCC pin has range of 1.67 – 3.6V and is used enable/disable the CRN120_VCC supply voltag, serving as a reset and a way to control when the CRN120 is on

### Field Detection Pin

FD pin can be used as a trigger for the host system to indicate the presence of the NFC field.

- The maximum delay from NFC field ON to FD pin HIGH is typically 30 us.
- The maximum delay from NFC field OFF to FD pin LOW is typically 200 us without load

###  Event Detection Pin

The event detection pin based on open-drain implementation provides the capability to\
trigger an external device (e.g. Controller) or switch on the connected circuitry by an\
external power management unit depending on activities on the NFC interface.

As the event detection pin functionality is operated via NFC field power, VCC supply for\
the tag itself is not required.

The conditions for pulling the event detection signal to low, ED_ON can be:

- The detection of a valid command (Start of Communication)
- The selection of the IC (through the NFC SELECT command)

The conditions for releasing the event detection signal defined with ED_OFF can be:
- The absence of the NFC field
- The detection of the HALT state
- The NFC interface has read the last part of the NDEF message defined with LAST_NDEF_BLOCK

## CRN120 Memory Map

>[!IMPORTANT] FOR I2C YOU NEED TO KNOW:
>
> - Minimum transfer size for I2C is **16 bytes**
>
>>[!NOTE] This is because the memory map of the device is arranges in blocks of 16 bytes which are, from the perspective of I2C, registers that should be addressed with the first byte being the address
>
> - There's 4 Blocks (registers) that are going to practically br used
>   - 0th Block registers (ADDR, SNR, CC)
>   - Configuration Register
>   - Session Register
>   - User Memory Register (SRAM)\
>Optionally one can use AUTH0 register for password protection

##  CRN120 Configuration and Session Registers

### Configuration Register - (I2C_ADDR - 0x3Ah, NFC_ADDR - 0xE8-E9)

| 0      | 1               | 2                 | 3       | 4       | 5             | 6            | 7   |
| ------ | --------------- | ----------------- | ------- | ------- | ------------- | ------------ | --- |
| NC_REG | LAST_NDEF_BLOCK | SRAM_MIRROR_BLOCK | WDT_LSB | WDT_MSB | I2C_CLOCK_STR | **REG_LOCK** | RFU |

### Session Register - (I2C_ADDR - 0xFEh, NFC_ADDR - 0xEC-0xED)

| 0      | 1               | 2                 | 3       | 4       | 5             |     6      |   7 |
| ------ | --------------- | ----------------- | ------- | ------- | ------------- | :--------: | --: |
| NC_REG | LAST_NDEF_BLOCK | SRAM_MIRROR_BLOCK | WDT_LSB | WDT_MSB | I2C_CLOCK_STR | **NS_REG** | RFU |

CRN120 behavior can be configured and read in two separate locations depending if the\
configurations shall be effective within the communication session (use session registers)\
or by default after Power-On Reset (POR) (use configuration registers).

The configuration registers of pages E8h to E9h (Sector 0 - see Table 9) via the NFC\
nterface or block 3Ah via the I°C interface are used to configure the default behavior

of the CRN120. Those bit values are stored in the EEPROM and represent the default\
settings to be effective after POR. Their values can be read and written by both interfaces\
when applicable and when not locked by the register lock bits (see REG_LOCK in

For NFC charging applications, it is recommended to set REG_LOCK byte to 03h as last\
step of personalization.

Both, the session and the configuration registers have the same configuration options and parameters except the REG_LOCK bits,\
which are only available in the configuration register and the NS_REG bits which are only available in the session register.\
After POR, the content of the configuration register is loaded into the session register

The values of both registers can be changed during a communication session.If the desired effect should be visible immediately, but only for the current communication session,\
the session registers must be used. After POR, the session registers values will again contain the configuration register values as before.

To change the default behavior, changes to the configuration register are needed, but the related effect will only be visible after the next POR.\
To make the effect immediately and after next POR visible, changes to configuration and session registers are needed.
